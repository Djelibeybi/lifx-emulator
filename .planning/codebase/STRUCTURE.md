## Directory Purposes

**`packages/lifx-emulator-core/src/lifx_emulator/devices/`:**
- Purpose: Device domain objects and lifecycle.
- Contains: `device.py` (`EmulatedLifxDevice`, `STATE_CHANGING_PACKETS`, `StateChangeCallback`), `manager.py` (`IDeviceManager`, `DeviceManager`, callbacks), `states.py` (`DeviceState` and sub-state dataclasses, `_ATTRIBUTE_ROUTES`, `_OPTIONAL_DEFAULTS`), `persistence.py` (`DevicePersistenceAsyncFile`, `DEFAULT_STORAGE_DIR`), `state_serializer.py`, `state_restorer.py` (`StateRestorer`, `NullStateRestorer`), `observers.py` (`PacketEvent`, `ActivityObserver`, `ActivityLogger`, `NullObserver`).
- Key files: `device.py`, `manager.py`, `states.py`.

**`packages/lifx-emulator-core/src/lifx_emulator/handlers/`:**
- Purpose: One `PacketHandler` subclass per LIFX packet type, grouped by protocol namespace.
- Contains: `base.py` (`PacketHandler` ABC), `registry.py` (`HandlerRegistry`), `device_handlers.py` (types 2-59, `ALL_DEVICE_HANDLERS`), `light_handlers.py` (101-149), `multizone_handlers.py` (501-512), `tile_handlers.py` (701-720), `sensor_handlers.py` (401/402), `button_handlers.py` (905-911), `__init__.py` (`create_default_registry()`).
- Key files: `__init__.py` is where new handler groups are registered.

**`packages/lifx-emulator-core/src/lifx_emulator/protocol/`:**
- Purpose: Binary wire format.
- Contains: `header.py` (`LifxHeader`), `base.py` (`Packet`), `serializer.py`, `protocol_types.py` (`LightHsbk`, `TileStateDevice`, `Button*`, enums), `const.py`, `packets.py` (**generated**), `generator.py`.
- Key files: `packets.py` (read-only), `generator.py`.

**`packages/lifx-emulator-core/src/lifx_emulator/products/`:**
- Purpose: Product capability data.
- Contains: `registry.py` (**generated** `ProductRegistry`, `ProductInfo`, `ProductCapability`, `get_product`, `get_registry`), `specs.py` + `specs.yml` (emulator defaults: zone counts, tile dimensions, firmware, uplight zones, button counts), `generator.py`.
- Key files: `specs.yml` is the editable source of per-product defaults.

**`packages/lifx-emulator-core/src/lifx_emulator/factories/`:**
- Purpose: Device construction.
- Contains: `builder.py` (`DeviceBuilder`), `factory.py` (`create_device`, `create_color_light`, `create_infrared_light`, `create_hev_light`, `create_multizone_light`, `create_tile_device`, `create_color_temperature_light`, `create_switch`), `serial_generator.py`, `default_config.py` (`DefaultColorConfig`), `firmware_config.py` (`FirmwareConfig`).

**`packages/lifx-emulator-core/src/lifx_emulator/scenarios/`:**
- Purpose: Fault-injection configuration.
- Contains: `manager.py` (`HierarchicalScenarioManager`, `get_device_type`), `models.py` (`ScenarioConfig` Pydantic), `persistence.py` (`ScenarioPersistenceAsyncFile`).

**`packages/lifx-emulator-core/src/lifx_emulator/repositories/`:**
- Purpose: Storage abstractions.
- Contains: `device_repository.py` (`IDeviceRepository`, `DeviceRepository`), `storage_backend.py` (`IDeviceStorageBackend`, `IScenarioStorageBackend`).

**`packages/lifx-emulator/src/lifx_emulator_app/api/routers/`:**
- Purpose: HTTP/WS endpoint definitions only; no business logic.
- Contains: `monitoring.py` (`/api/stats`, `/api/activity`), `devices.py` (`/api/devices`), `scenarios.py` (`/api/scenarios/{global|devices|types|locations|groups}`), `products.py` (`/api/products`), `websocket.py` (`/ws`).
- Key files: Each exposes `create_<name>_router(...)`.

**`packages/lifx-emulator/src/lifx_emulator_app/api/services/`:**
- Purpose: Business logic between routers and the core server.
- Contains: `device_service.py`, `scenario_service.py`, `websocket_manager.py` (`Topic`, `MessageType`, `WebSocketManager`), `event_bridge.py` (`wire_device_events`, `wire_device_state_events`, `WebSocketActivityObserver`, `WebSocketStateChangeObserver`, `StatsBroadcaster`).

**`packages/lifx-emulator/src/lifx_emulator_app/api/mappers/`:**
- Purpose: Domain → API model conversion.
- Contains: `device_mapper.py` (`DeviceMapper.to_device_info`, `to_device_info_list`).

**`packages/lifx-emulator/src/lifx_emulator_app/api/static/`:**
- Purpose: Compiled dashboard served by FastAPI.
- Contains: `index.html`, `_app/`, `robots.txt` (all produced by `vite build`; `_app`, `index.html`, `robots.txt` are gitignored).

**`packages/lifx-emulator/frontend/src/lib/`:**
- Purpose: Dashboard implementation.
- Contains: `components/` (`Header`, `StatsBar`, `DeviceToolbar`, `DeviceCard`, `DeviceList`, `DeviceTable`, `ActivityLog`, `ScenarioPanel`, `Pagination`, `Visualizer`), `stores/` (`connection`, `devices`, `stats`, `activity`, `ui`, `theme`, `scenarios`, `products`), `utils/api.ts`, `utils/color.ts`, `types.ts`.

**`packages/*/tests/`:**
- Purpose: pytest suites, one flat directory per package.
- Contains: Core: `conftest.py` with device fixtures, `test_device.py`, `test_server.py`, `test_*_handlers*.py`, `test_scenario_*.py`, `test_repositories.py`, `test_async_storage.py`, `test_integration.py`, generator tests. App: `conftest.py`, `test_cli*.py`, `test_config.py`, `test_api*.py`, `test_scenario_service.py`, `test_websocket.py`, `test_export_config.py`.

**`docs/`:**
- Purpose: User and developer documentation built with Zensical/mkdocstrings (`mkdocs.yml`).
- Contains: `architecture/` (overview, packet-flow, device-state, protocol, decisions), `library/`, `cli/`, `guide/`, `tutorials/`, `reference/`, `development/code-navigation.md`, `changelogs/`, `superpowers/` (dated specs and plans).

**`conductor/`:**
- Purpose: Product and engineering guidance for AI-assisted workflows.
- Contains: `product.md`, `product-guidelines.md`, `tech-stack.md`, `workflow.md`, `code_styleguides/python.md`, `code_styleguides/typescript-svelte.md`, `tracks/`.

## Naming Conventions

**Files:**
- Python modules: `snake_case.py`; handler modules end in `_handlers.py` (`light_handlers.py`); persistence modules are named `persistence.py` inside their domain package; Protocol interface modules describe the abstraction (`storage_backend.py`, `device_repository.py`).
- Tests: `test_<module>.py`; extended coverage suites use `_extended` suffix (`test_light_handlers_extended.py`); edge cases use `_edge_cases`.
- Svelte components: `PascalCase.svelte` (`DeviceCard.svelte`); rune stores: `camelCase.svelte.ts` (`devices.svelte.ts`); utilities: `camelCase.ts`.
- SvelteKit routes: `+page.svelte`, `+layout.svelte`, `+layout.ts`.
- Docs: `kebab-case.md`; numbered tutorials `01-first-device.md`; dated specs `YYYY-MM-DD-<slug>.md` under `docs/superpowers/`.

**Python symbols:**
- Classes `PascalCase`; Protocol interfaces prefixed `I` (`IDeviceManager`, `IDeviceRepository`, `IDeviceStorageBackend`); handler classes `<Verb><Noun>Handler` matching the packet (`SetColorHandler`, `ExtendedGetColorZonesHandler`); async file backends `<Domain>PersistenceAsyncFile`.
- Handler list constants `ALL_<NAMESPACE>_HANDLERS`; module-level singletons prefixed `_` (`_registry`, `_specs_registry`); frozensets/consts `UPPER_SNAKE` (`STATE_CHANGING_PACKETS`, `LIFX_UDP_PORT`).
- Private helpers prefixed `_` (`_send_ack`, `_apply_error_scenarios`, `_add_device_endpoints`).
- Factory functions `create_<thing>()`; router factories `create_<name>_router()`; app factory `create_api_app()`.
- Service exceptions `<Noun><Condition>Error` (`DeviceNotFoundError`, `ScenarioNotFoundError`).
- Sub-state dataclasses `<Aspect>State` (`MultiZoneState`, `MatrixState`, `ButtonsState`).
- Packet classes are nested by namespace: `Device.GetService`, `Light.StateColor`, `MultiZone.ExtendedStateMultiZone`, `Tile.State64`.

**Directories:**
- Python packages are plural nouns per layer (`devices/`, `handlers/`, `scenarios/`, `repositories/`, `factories/`, `products/`, `routers/`, `services/`, `mappers/`).
- Workspace member directories match PyPI names (`lifx-emulator-core`, `lifx-emulator`); import names use underscores (`lifx_emulator`, `lifx_emulator_app`).

**API routes:**
- Prefix `/api`; plural resources (`/api/devices`, `/api/scenarios`, `/api/products`); scenario scopes as plural path segments (`/api/scenarios/devices/{serial}`, `/types/{type}`, `/locations/{label}`, `/groups/{label}`, `/api/scenarios/global`); WebSocket at `/ws`.

**Git / release:**
- Conventional commits with monorepo scopes; release tags `core-vX.Y.Z` and `app-vX.Y.Z`; commits signed with `git commit -s`.

## Where to Add New Code

**New packet handler (existing namespace):**
- Implementation: add a `PacketHandler` subclass to the matching `packages/lifx-emulator-core/src/lifx_emulator/handlers/<namespace>_handlers.py`, set `PKT_TYPE = <Namespace>.<Packet>.PKT_TYPE`, return `list[Packet]`, and append an instance to that module's `ALL_*_HANDLERS`.
- If the packet mutates state, add its type to `STATE_CHANGING_PACKETS` in `devices/device.py:40-57` so WebSocket `device_updated` events fire.
- If the packet needs a capability gate, extend `_should_handle_packet` in `devices/device.py:246`.
- Tests: `packages/lifx-emulator-core/tests/test_<namespace>_handlers_extended.py` (or a new `test_<namespace>_handlers.py`), using fixtures from `tests/conftest.py`.

**New packet namespace (new type range):**
- Create `handlers/<namespace>_handlers.py` with `ALL_<NAMESPACE>_HANDLERS`; register in `create_default_registry()` in `handlers/__init__.py` and export from `__all__`.
- Add the range to `_should_handle_packet` and, if relevant, to `get_device_type()` in `scenarios/manager.py`.
- Packet definitions come from regenerating `protocol/packets.py`, not hand edits.

**New device capability or state field:**
- Add a sub-state dataclass or field in `devices/states.py`; add routing entries to `DeviceState._ATTRIBUTE_ROUTES` and defaults to `_OPTIONAL_DEFAULTS`; add a `has_<capability>` flag on `DeviceState`.
- Populate it in `DeviceBuilder` (`factories/builder.py`, a `_create_<capability>_state()` helper) and wire product detection from `ProductInfo`.
- Persist it: extend `devices/state_serializer.py` and `devices/state_restorer.py`.
- Expose it: `api/models.py` (`DeviceInfo`), `api/mappers/device_mapper.py`, frontend `lib/types.ts` and components.
- Tests: `tests/test_device_state_new_fields.py`, `tests/test_state_restorer.py`, `tests/test_backwards_compatibility.py`.

**New product default (zone count, tile size, firmware, buttons):**
- Edit `packages/lifx-emulator-core/src/lifx_emulator/products/specs.yml`; accessor helpers in `products/specs.py`. Tests in `tests/test_products_specs.py` / `tests/test_specs.py`.

**New scenario option:**
- Add the field to `ScenarioConfig` in `scenarios/models.py` (and its `from_dict`/`to_dict`, key converters); merge it in `HierarchicalScenarioManager.get_scenario_for_device` (`scenarios/manager.py:174`); apply it in `EmulatedLifxDevice.process_packet` or `EmulatedLifxServer._process_device_packet`; mirror in `ScenarioDefinition` (`lifx_emulator_app/config.py`) and `_scenario_def_to_core` (`__main__.py:513`); persist via `scenarios/persistence.py`.
- Tests: `tests/test_scenario_manager.py`, `tests/test_scenario_persistence.py`, app `tests/test_scenario_service.py`.

**New factory function:**
- Add to `factories/factory.py` delegating to `create_device(product_id, ...)`; export in `factories/__init__.py` and (if part of the top-level API) `lifx_emulator/__init__.py`.

**New REST endpoint:**
- Router: add to the matching file in `packages/lifx-emulator/src/lifx_emulator_app/api/routers/` inside its `create_<name>_router` (or a `_add_*_endpoints` helper to keep McCabe ≤ 10); new resource → new `routers/<resource>.py` with `create_<resource>_router()` included in `api/app.py`.
- Logic: a method on the relevant service in `api/services/`; raise typed exceptions, map to `HTTPException` in the router.
- Models: `api/models.py`; mapping in `api/mappers/`.
- Frontend client: `frontend/src/lib/utils/api.ts`.
- Tests: `packages/lifx-emulator/tests/test_api.py` / `test_api_validation.py` (httpx `TestClient`).

**New WebSocket message or topic:**
- Add to `Topic`/`MessageType` in `api/services/websocket_manager.py`, a `broadcast_<event>` method, and a producer in `api/services/event_bridge.py`; handle it in `frontend/src/lib/stores/connection.svelte.ts` `handleMessage`; type it in `frontend/src/lib/types.ts`. Tests in `packages/lifx-emulator/tests/test_websocket.py`.

**New CLI command or flag:**
- Command: `@app.command` function in `__main__.py`; flag: parameter on `run()` grouped with an existing `cyclopts.Group` (`__main__.py:56-64`), plus the matching field on `EmulatorConfig` in `config.py` and handling in `merge_config`.
- Tests: `packages/lifx-emulator/tests/test_cli.py`, `test_cli_validation.py`, `test_config.py`.

**New dashboard UI:**
- Component: `frontend/src/lib/components/<Name>.svelte`, export from `components/index.ts`.
- State: `frontend/src/lib/stores/<name>.svelte.ts` (Svelte 5 runes), export from `stores/index.ts`.
- Wire into `frontend/src/routes/+page.svelte` tabs; rebuild with `npm run build` so `api/static/` updates.

**Utilities / shared helpers:**
- Core protocol helpers: `protocol/serializer.py` or `protocol/base.py`.
- Colour maths shared by handlers: module-level private functions in the handler file (pattern: `_compute_average_color` in `handlers/light_handlers.py:18`).
- App-wide helpers: keep in the owning service; there is no `utils/` package in Python—avoid introducing one unless two services share the code.

**New storage backend:**
- Implement `IDeviceStorageBackend` or `IScenarioStorageBackend` from `repositories/storage_backend.py`; inject via `create_device(storage=...)` / `EmulatedLifxServer(storage=..., scenario_storage=...)`. Tests alongside `tests/test_async_storage.py`.
