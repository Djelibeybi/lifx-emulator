**`devices/state_serializer.py`** — add `"connectivity": str(device_state.connectivity)` to the
unconditional dict literal in `serialize_device_state()`, alongside `serial` and `label`. It is not
guarded by an `if has_X:` block: every device has a connectivity. `str()` renders the bare value
because `Connectivity` defines `__str__ = str.__str__`. Use `str(...)` rather than `.value`: a caller
who bypasses the factories and builds a `NetworkState` with a raw `"thread"` string still serialises
correctly, whereas `.value` would raise `AttributeError` on that path. Put that reason in a one-line
comment beside the entry, because `.value` looks like the more explicit choice and would otherwise be
"tidied up" later. The `__str__` dependency is not left implicit: the Task 1 verify command asserts
the serialised JSON contains the exact substring `"connectivity": "thread"`, which fails loudly if
`__str__ = str.__str__` is ever dropped from the enum. Addresses review concern: Antigravity LOW,
`L421@c667eb9` — considered, and `str()` deliberately kept with the rationale recorded.
Do NOT add `wifi_signal`, `version_major`,
`version_minor` or `advertised_services` — `wifi_signal` is re-derived at build time from the
restored connectivity, and the other three are a pre-existing round-trip gap the SPEC explicitly
leaves unchanged. Leave `deserialize_device_state()` alone: connectivity is consumed by the builder,
not by the state composer.
