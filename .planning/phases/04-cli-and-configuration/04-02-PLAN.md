<objective>
Add server-level advertised mDNS address defaults to the core library as a published, validated,
read-only feature (D-01, D-02), expose the core validators through the devices barrel, and prove the
library defaults are unchanged (SPEC R6 core side, R8, CFG-06).

Purpose: The standalone app passes `--mdns-ipv4-address` / `--mdns-ipv6-address` straight through
to the core in plan 04-05, and Phase 5 API-created devices inherit the default with no extra work.
The barrel exports let plans 04-04 and 04-05 reuse the core validation rules.

Output: `MdnsAddressDefaults`, a three-tier `resolve_address()`, new `EmulatedLifxServer`
keyword-only parameters and read-only properties, barrel exports, a core README note and
`test_mdns_defaults.py`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Library caller to EmulatedLifxServer constructor | Caller-supplied address strings decide what the responder advertises |
| Responder to the LAN | Advertised A/AAAA records are visible to any mDNS client that can reach the selected (or, per AR-06, another) interface |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-05 | Information Disclosure | server.py _validated_mdns_defaults | medium | mitigate | Reuse validate_mdns_address for the matching family so link-local, scoped, unspecified, multicast and broadcast defaults are rejected at construction |
| T-04-06 | Tampering | EmulatedLifxServer.mdns_ipv4_address / mdns_ipv6_address | low | mitigate | Read-only properties with no setter; values fixed for the server lifetime (D-02) |
| T-04-07 | Denial of Service | EmulatedLifxServer.__init__ and start() | medium | mitigate | Validate before device admission and keep the start() preflight loop so an unusable fallback raises before any endpoint is committed, naming the device |
| T-04-08 | Information Disclosure | zeroconf receive interface on Linux (AR-06) | low | accept | Accepted in Phase 3 (AR-06) and documented in the core README; this plan changes only which address is advertised, never the interface zeroconf binds |
</threat_model>
