<objective>
Emit mDNS advertisement lifecycle events (registered, updated, withdrawn, started, stopped, failed)
from the core responder and server into the existing activity observer through a new optional
`on_mdns_event` hook, without touching LIFX packet statistics or third-party observers (SPEC R7
core side, R8, D-04 to D-09).

Purpose: `/api/activity` and the WebSocket activity topic (plan 04-06) can only show what the core
reports. zeroconf answers individual queries internally, so lifecycle events are the complete,
honest activity surface.

Output: `PacketEvent.kind`, `on_mdns_event` on `ActivityLogger`/`NullObserver`, emission points in
`mdns.py` and `server.py`, a README note and `test_mdns_activity.py`.
</objective>

<assumption_delta_decision>
Detector signals: pluralization ("alongside": the activity stream gains a second event family next to
LIFX packets) and optional (the `on_mdns_event` observer hook is optional).
- Primary noun: the activity event, represented by `PacketEvent` and discriminated by `kind`.
- Decision: add-alongside, locked by D-08 (reuse `PacketEvent` with `kind: str = "lifx"` instead of
  promoting a new general activity-event type), so one type stays in the logger deque and maps one to
  one onto the API `ActivityEvent`. The optional hook is no-change to the `ActivityObserver` Protocol
  (D-07 keeps third-party observers working).
- Accepted debt: the name `PacketEvent` now also covers non-packet events. A third event family, or
  mDNS events needing fields packets lack (D-05 rejected a `detail` field), would force promoting a
  general activity-event type with `PacketEvent` as one variant.
- Companion invariant test: plan 04-06 Task 1 asserts both variants round-trip through the API
  `ActivityEvent` model with the right `kind`.
</assumption_delta_decision>

From `mdns.py` (after 04-02): `MdnsResponder.start(devices)` constructs `AsyncZeroconf(interfaces=[self.address], ip_version=IPVersion.V4Only)` then reconciles; `_operation(operation, info)` awaits `async_register_service`/`async_update_service`/`async_unregister_service` and then the returned announcement; `_reconcile(infos)` unregisters removed names (moving them to `_tombstones`), updates changed existing records, and registers new names or updates a tombstone; `stop()` unregisters every owned service then awaits `owner.async_close()`; `ServiceInfo.name` is `<serial>._lifx._udp.local.` and `ServiceInfo.parsed_addresses()` returns the advertised address strings.

From `server.py`: `_record_mdns_failure(error)` ignores `asyncio.CancelledError`, unwraps `MdnsUpdateError.__cause__`, sets `_mdns_error` and `_mdns_status = MdnsStatus.FAILED` and logs; it is the single failure funnel reached from `_start_mdns_locked`, `_stop_mdns_locked`, `_mdns_failed` (runtime) and `_apply_mdns_failure`. `_open_mdns_locked()` constructs the responder then calls `await responder.start(self.get_all_devices())`. `retry_mdns()` calls `_stop_mdns_locked()` then `_start_mdns_locked()`. `activity_observer` may be replaced at runtime (the API does this in `create_api_app`).

Test support: `make_server`, `FakeOwner` in `test_mdns_responder.py` (its fake lacks `async_update_service`, so this plan's tests define a local owner double with register, update, unregister and close); `requires_ipv6_loopback` in `test_ipv6_transport.py`. Every server `start()` binds a V6-only socket; responder-level tests with a monkeypatched `mdns.AsyncZeroconf` need no LIFX socket.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Core server to activity observer | Observers may be third-party code or the app's WebSocket bridge and may raise |
| zeroconf and OS errors to activity text | Exception text crosses into packet_name, which reaches logs, /api/activity and browsers |

| T-04-09 | Denial of Service | server.py _emit_mdns_event and mdns.py _notify | high | mitigate | Wrap every hook call in try/except Exception with logger.exception (D-09); tests prove a raising observer leaves mDNS running and LIFX answering |
