<interfaces>
From plan 04-03 (core): `PacketEvent(..., kind: str = "lifx")`; `from lifx_emulator.mdns import mdns_activity_event` builds `PacketEvent(direction="mdns", packet_type=0, packet_name="mDNS <action>", addr=..., device=serial or None, target=None, kind="mdns")`; the server calls `getattr(self.activity_observer, "on_mdns_event", None)` inside try/except; `ActivityLogger.on_mdns_event` stores `{"timestamp", "direction", "packet_type", "packet_name", "device", "target", "addr", "kind"}`.

From the app: `create_api_app(server)` builds `ws_manager = WebSocketManager(server)` and `background_task_tracker = WebSocketEventQueue(...)`, exposes both on `app.state`, and immediately replaces `server.activity_observer` with `WebSocketActivityObserver(ws_manager, previous_activity, task_tracker=background_task_tracker)`. The CLI starts the API only after `server.start()`, so startup events reach clients through the `sync` message's `activity` list (`WebSocketManager._send_full_sync` reads `server.get_recent_activity()`); later events are live `activity` broadcasts. `WebSocketEventQueue.schedule_factory` starts its workers on the running loop when first used. `WebSocketManager.connect(ws)`, `subscribe(ws, topics)` and `handle_message(ws, {"type": "sync"})` accept a MagicMock websocket with AsyncMock `accept`/`send_json`; a `send_json` that raises disconnects that client.

Existing tests assert the exact rx/tx broadcast dicts (`test_websocket.py:547-594`) and `test_websocket.py` has `RecordingTaskTracker`. `GET /api/activity` returns `[ActivityEvent(**event) for event in server.get_recent_activity()]`.

Frontend: `frontend/src/lib/types.ts` `ActivityEvent.direction: 'rx' | 'tx'`; `ActivityLog.svelte` renders `act.direction.toUpperCase()` and styles every non-rx row with `activity-tx`, so mDNS rows render as "MDNS" without component changes. `frontend/node_modules` and `.svelte-kit` are git-ignored; CI does not build the frontend.
</interfaces>
